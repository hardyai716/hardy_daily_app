## v29 习惯目标规则

- 目标周期：`day`、`week`、`month`；周为周一至周日，月为自然月。
- 普通目标：每天仍保存一条数值打卡，周/月进度按周期内每日数值求和。
- 时间目标：第一版只支持每日；`23:30` 记为 1410，`00:30` 记为 1470，目标 `01:00` 记为 1500。
- 日期归属：凌晨 04:00 前的时间记录归入前一天，因此跨午夜比较不会反转。
- 兼容性：旧习惯缺少新字段时自动补为“每日、至少达到”；原打卡稳定 ID `习惯ID/日期` 不变。
- 云端结构：周期、规则、目标时间和凌晨分界保存在习惯定义的“完整数据”中，不新增或修改云表字段。
- 展示语义：卡片展示当前周期进度；热力图表示当天是否发生行为，不把周/月达标结果重复涂到每天。

## 2. 修复后的保存链路

提交、修改或删除 → 对比当前业务内容 → 生成稳定 ID 和待同步任务 → **业务内容与任务在同一次 localStorage 写入中保存** → 准备表结构 → 读取并合并 → 按条写入 → 读回核对 → 确认完成。

| 场景 | 行为 |
| --- | --- |
| 草稿输入 | 只保存本机，不因每次键盘输入重新读取所有云端数据 |
| 缺 SDK | 显示“已存本机 · 未连接云端”，保留任务 |
| 缺新表、缺字段、字段类型不符 | 明确显示原因，禁止不完整写入 |
| 网络失败 | 保留持久任务；最多三次自动退避重试，支持手动重试和网络恢复重试 |
| 刷新或关闭后重开 | 重新加载任务，不保存临时请求锁 |
| 旧查询晚返回 | 先捕获新修改，再按 ID 和待同步任务合并 |
| 新增已成功但响应丢失 | 查询稳定 ID 和变更 ID，找到后确认，不再次新增 |
| 新增失败且结果始终不明 | 保留任务并继续提供查询；“核对后重新新增”需要用户确认，提示延迟请求仍可能造成重复 |
| 两端改不同字段 | 基于共同版本合并 |
| 两端改同一字段 | 保留双方内容，显示“保留本机内容 / 采用云端内容” |
| 删除 | 保存删除标记并同步，避免刷新后无提示恢复 |
| 本机空间不足 | 显示本机保存失败，停止云写；当前页内容可导出 |
| 本机 JSON 损坏 | 保留原字符串，不覆盖它、不写云；导出恢复副本 |
| 同设备多页面 | Web Locks 只允许一个编辑页，第二页提示关闭原页后刷新 |

“记录已同步”只指业务记录和四类个人设置；表单草稿、筛选器等仍在本机。桌面和手机均有同步说明、重试和完整备份按钮。

1. 从原设备缓存恢复实际习惯定义，保存为 `private_work/habit-definitions.json` 数组，包含原字符串 ID、名称、类型、目标、单位、主题色和归档状态。

```bash

  --definitions private_work/habit-definitions.json \

  --mapping private_work/habit-row-map.json
```

- 页内显示“提醒意愿”只是字段保存，不会在关闭网页后推送通知。
- 封面仍保存为压缩数据内容。v26 增加单张和本机总容量保护；后续可迁移到受权限控制的文件存储。
- 完整备份包含当前状态、待同步任务和冲突信息；v22 已提供校验、预览、合并和完全替换恢复。
- v29 延续现有“新增/归档”习惯管理；已有习惯要改周期需归档后重建，历史打卡仍保留。后续若增加目标编辑，必须使用“下个周期生效”的版本记录，不能重算旧周期。
- 删除继续使用云端软删除标记，不自动物理清理。主状态不显示数量，诊断详情中可查看；平台没有已验证的安全保留期和条件删除能力，因此不能自动删除云端墓碑。
- v15 删除标记不能被 v14 正确理解。回滚须同时处理数据形态，不能只回传旧 HTML。
- v29 已提交为云端版本 26 并更新现有公开链接。后续页面变更仍须使用官方事务链路，发布状态只按用户当次明确指令调整。
